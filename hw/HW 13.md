## Развёртывание YugabyteDB

### 1. Добавление Helm-репозитория

```
helm repo add yugabytedb https://charts.yugabyte.com
helm repo update
```

### 2. Создание namespace

```
kubectl create namespace yb-demo
```

### 3. Helm values — `yugabyte-values.yaml`

```
image:
  tag: 2025.1.0.0-b52

replicas:
  master: 3
  tserver: 3

resource:
  master:
    requests:
      cpu: 2
      memory: 4Gi
    limits:
      cpu: 2
      memory: 4Gi
  tserver:
    requests:
      cpu: 4
      memory: 8Gi
    limits:
      cpu: 4
      memory: 8Gi

storage:
  master:
    count: 1
    size: 10Gi
    storageClass: "yc-network-ssd"
  tserver:
    count: 2
    size: 20Gi
    storageClass: "yc-network-ssd"

gflags:
  tserver:
    log_segment_size_mb: "64"
    ysql_pg_conf_csv: "yb_enable_cbo=on,yb_enable_bitmapscan=on"
    yb_enable_read_committed_isolation: "true"
    ysql_max_connections: "300"
  master:
    load_balancer_initial_delay_secs: "120"

enableNodeAffinity: true
```

### 4. Установка YugabyteDB

```
helm install yugabyte yugabytedb/yugabyte \
  --namespace yb-demo \
  --values yugabyte-values.yaml \
  --timeout 15m \
  --wait

kubectl get pods -n yb-demo -w
```

### 5. Проверка состояния кластера

```
# Зайти в ysqlsh

  /home/yugabyte/bin/ysqlsh -h yb-tserver-0

# Web UI через port-forward
kubectl port-forward -n yb-demo svc/yb-master-ui 7000:7000
```

### 6. DDL — `sql/schema_yb.sql`

```

\c bench_db

    trip_id           BIGSERIAL,

    tpep_pickup       TIMESTAMP,
    tpep_dropoff      TIMESTAMP,

    trip_distance     NUMERIC(8,2),
    pickup_longitude  NUMERIC(18,14),
    pickup_latitude   NUMERIC(18,14),
    dropoff_longitude NUMERIC(18,14),
    dropoff_latitude  NUMERIC(18,14),

## Загрузка датасета

**Датасет:** NYC Yellow Taxi Trips 2015 (12 файлов, ~14 ГБ, ~146M строк) 
**Источник:** https://github.com/toddwschneider/nyc-taxi-data

### 1. Pod-загрузчик — `k8s/loader-pod.yaml`

```
apiVersion: v1
kind: Pod
metadata:
  name: data-loader
  namespace: yb-demo
spec:
  restartPolicy: Never
  containers:
  - name: loader
    image: postgres:16
    command: ["sleep", "86400"]
    resources:
      requests:
        cpu: "2"
        memory: "4Gi"
```

```
kubectl apply -f k8s/loader-pod.yaml
kubectl exec -it -n yb-demo data-loader -- bash
```

### 2. Скачивание данных (внутри pod)

```
apt-get update && apt-get install -y wget
mkdir /data && cd /data

for month in $(seq -w 1 12); do
  url="https://storage.googleapis.com/tlc-trip-data/2015/yellow_tripdata_2015-${month}.csv"
  echo "Downloading month ${month}..."
  wget -q "$url" -O "trips_2015_${month}.csv"
done

du -sh /data/
```

### 3. Загрузка в YugabyteDB

```
export PGPASSWORD=yugabyte
export PGHOST=yb-tserver-0.yb-tservers.yb-demo.svc.cluster.local
export PGPORT=5433
export PGDATABASE=bench_db
export PGUSER=yugabyte

# Параллельная загрузка в 4 потока
ls /data/trips_2015_*.csv | xargs -P 4 -I{} \
  psql -c "\COPY trips(vendor_id,tpep_pickup,tpep_dropoff,passenger_count,
    trip_distance,pickup_longitude,pickup_latitude,dropoff_longitude,
    dropoff_latitude,payment_type,fare_amount,tip_amount,total_amount)
    FROM '{}' CSV HEADER"

# Реальное время загрузки: ~47 минут
# Строк загружено: 146 112 989
```

### 4. Загрузка в PostgreSQL

```
export PGPASSWORD=benchpass
export PGHOST=postgres.pg-bench.svc.cluster.local
export PGPORT=5432
export PGDATABASE=bench_db

## Настройка теста

### Тестовые запросы

#### Q1 — COUNT + GROUP BY

```
-- sql/q1_agg.sql
SELECT payment_type, COUNT(*), ROUND(AVG(total_amount), 2)
FROM trips
GROUP BY payment_type
ORDER BY payment_type;
```

#### Q2 — Фильтрация по диапазону дат (index scan)

```
-- sql/q2_range.sql
SELECT vendor_id, COUNT(*), SUM(fare_amount)
FROM trips
WHERE tpep_pickup >= '2015-06-01'
  AND tpep_pickup <  '2015-07-01'
GROUP BY vendor_id;
```

#### Q3 — Топ-10 дорогих поездок (sort + limit)

```
-- sql/q3_topk.sql
SELECT trip_id, vendor_id, tpep_pickup, total_amount
FROM trips
ORDER BY total_amount DESC
LIMIT 10;
```

## Проблемы и решения

### Проблема 1: `ERROR: duplicate key value` при COPY в YugabyteDB

```
ERROR:  duplicate key value violates unique constraint "trips_pkey"
DETAIL:  Key (trip_id)=(0) already exists.
```

**Причина:** CSV-файлы NYC Taxi содержат строки с `trip_id=0` или NULL. YugabyteDB строже PostgreSQL в части NOT NULL-проверок при COPY.

**Решение:** Загружать без явного `trip_id` — BIGSERIAL генерирует значения автоматически:

---

### Проблема 2: Медленная загрузка данных в YugabyteDB

**Причина:** Каждый INSERT (через COPY) ждёт Raft-консенсуса (RF=3). Загрузка в 1.6x медленнее PostgreSQL.

**Решение по совету интернета:** Использовать параллельную загрузку в 4 потока:

```
ls /data/*.csv | xargs -P 4 -I{} \
  psql -h $YB_HOST -p 5433 -U yugabyte bench_db \
  -c "\COPY trips(...) FROM '{}' CSV HEADER"
```

---

### Проблема 3: Q3 (ORDER BY + LIMIT) очень медленный

**Причина:** Без индекса на `total_amount` YugabyteDB выполняет full scan всех шардов и глобальную сортировку на координаторе.

**Решение:** Добавить индекс:

```sql
CREATE INDEX idx_trips_total ON trips (total_amount DESC);
```

## Выводы

### Ключевые наблюдения

1. **YugabyteDB — не замена PostgreSQL, а его расширение.** Решает задачи масштабирования и HA, которые один PostgreSQL не умеет, но ценой latency (~3–5 мс Raft overhead на операцию записи).
    
2. **Шардирование важно планировать заранее.** `SPLIT INTO N TABLETS` при создании таблицы — критично для производительности при bulk-загрузке и range-запросах.
    
3. **Индексы сильно важны в YugabyteDB.** Без индекса full scan распределяется по всем шардам и собирается координатором — дороже, чем в PostgreSQL.
    
4. **PostgreSQL-совместимость высокая, но не 100%.** Выявлены различия в поведении `COPY`, обработке NULL, изоляции транзакций (по умолчанию Serializable vs Read Committed в PG).
