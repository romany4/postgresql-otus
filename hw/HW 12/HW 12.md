## Выполнение

### 1. Подготовка PostgreSQL

Скачиваем и загружаем датасет:

```bash

wget https://edu.postgrespro.ru/demo-20250901-2y.sql.gz
gunzip demo-20250901-2y.sql.gz

# Временные настройки postgresql.conf для ускорения загрузки
sudo tee -a /etc/postgresql/15/main/postgresql.conf <<EOF
shared_buffers = 512MB
effective_cache_size = 2GB
wal_level = minimal
max_wal_senders = 0
max_wal_size = 10GB
min_wal_size = 512MB
fsync = off
full_page_writes = off
checkpoint_timeout = 15min
synchronous_commit = off
autovacuum = off
work_mem = 38MB
maintenance_work_mem = 409MB
max_parallel_workers_per_gather = 4
max_parallel_workers = 4
EOF
sudo systemctl restart postgresql

# Загружаем
time psql -U postgres -f demo-20250901-2y.sql

# Возвращаем прежние параметры

# Перезапускаем
sudo systemctl restart postgresql
```

### 3. Разворачиваем CockroachDB

> CockroachDB недоступен для скачивания из РФ.

```bash
# На каждой из 3 нод CockroachDB
sudo tar -xzvf cockroach-v23.2.0.linux-amd64.tgz
sudo mv cockroach-v23.2.0.linux-amd64 /opt/cockroach

# Добавляем в /etc/hosts на всех нодах
echo "10.0.0.1 cdb1" | sudo tee -a /etc/hosts
echo "10.0.0.2 cdb2" | sudo tee -a /etc/hosts
echo "10.0.0.3 cdb3" | sudo tee -a /etc/hosts

# Сертификаты (на node-1)
sudo /opt/cockroach/cockroach cert create-ca \
    --certs-dir=/opt/cockroach/certs \
    --ca-key=/opt/cockroach/my-safe-directory/ca.key

sudo /opt/cockroach/cockroach cert create-node \
    localhost cdb1 cdb2 cdb3 \
    --certs-dir=/opt/cockroach/certs \
    --ca-key=/opt/cockroach/my-safe-directory/ca.key

sudo /opt/cockroach/cockroach cert create-client root \
    --certs-dir=/opt/cockroach/certs \
    --ca-key=/opt/cockroach/my-safe-directory/ca.key

# Копируем сертификаты на остальные ноды
scp -r /opt/cockroach/certs ubuntu@cdb2:/tmp/certs
scp -r /opt/cockroach/certs ubuntu@cdb3:/tmp/certs

# Запускаем кластер
ssh ubuntu@cdb1 'sudo /opt/cockroach/cockroach start \
    --certs-dir=/opt/cockroach/certs \
    --advertise-addr=cdb1 \
    --join=cdb1,cdb2,cdb3 \
    --cache=.25 --max-sql-memory=.25 --background'

ssh ubuntu@cdb2 'sudo /opt/cockroach/cockroach start \
    --certs-dir=/opt/cockroach/certs \
    --advertise-addr=cdb2 \
    --join=cdb1,cdb2,cdb3 \
    --cache=.25 --max-sql-memory=.25 --background'

ssh ubuntu@cdb3 'sudo /opt/cockroach/cockroach start \
    --certs-dir=/opt/cockroach/certs \
    --advertise-addr=cdb3 \
    --join=cdb1,cdb2,cdb3 \
    --cache=.25 --max-sql-memory=.25 --background'

# Инициализируем (один раз)
sudo /opt/cockroach/cockroach init \
    --certs-dir=/opt/cockroach/certs --host=cdb1
```

## Известные сложности и решения
Интернет говорит о следующих проблемах:

### 1. CockroachDB недоступен из РФ
**Проблема**: бинарник не скачивается напрямую.  
**Решение**: скачать через VPN заранее.

### 2. Тип `tstzrange` не поддерживается в CockroachDB
**Проблема**: колонка `routes.validity` имеет тип `tstzrange`.  
**Решение**: разбить на два поля `validity_start` и `validity_end TIMESTAMPTZ`. При JOIN вместо `validity @> scheduled_departure` использовать:
```sql
r.validity_start <= f.scheduled_departure AND f.scheduled_departure < r.validity_end
```

### 3. Тип `point` для координат
**Проблема**: `airports_data.coordinates` типа `point` не поддерживается.  
**Решение**: разбить на `longitude FLOAT` + `latitude FLOAT` при экспорте через `coordinates[0]` и `coordinates[1]`.

### 4. Тип `integer[]` (массив) для days_of_week
**Проблема**: CockroachDB не поддерживает `integer[]` в IMPORT INTO CSV.  
**Решение**: конвертировать в строку `array_to_string(days_of_week, ',')` при экспорте, хранить как `STRING`.

### 5. SERIAL создаёт hotspot
**Проблема**: `SERIAL` в распределённой БД генерирует монотонно возрастающие ID, что создаёт "горячую" ноду.  
**Решение**: использовать `INT8 DEFAULT unique_rowid()` — CockroachDB генерирует распределённые ID.

### 6. EXCLUDE USING gist не поддерживается
**Проблема**: темпоральное ограничение уникальности `routes` в PostgreSQL.  
**Решение**: убрать это ограничение в CRDB (оставить только PRIMARY KEY).

### 7. Функции bookings.lang() и bookings.now()
**Проблема**: пользовательские функции схемы не переносятся.  
**Решение**: в VIEW заменить `lang()` на хардкод `'en'`, `bookings.now()` на стандартный `now()`.

### 8. Внешний ключ на темпоральный ключ routes
**Проблема**: `flights.route_no` ссылается на `routes(route_no, validity_start)` — составной темпоральный FK.  
**Решение**: упростить до `FOREIGN KEY (route_no) REFERENCES routes(route_no)` без темпорального условия.

## Результаты
Написан небольшой скрипт проверки производительности запросов.

| Запрос | PostgreSQL | CockroachDB | Вывод |
|--------|-----------|-------------|-------|
| Q1 GROUP BY месяц | быстрее | медленнее | PG лучше на single-node аналитике |
| Q2 JOIN маршруты | быстрее | сопоставимо | PG оптимизатор зрелее |
| Q3 JOIN пассажиры | быстрее | медленнее | PG лучше на сложных JOIN |
| Q4 Window function | быстрее | медленнее | CRDB исторически слабее |
| Q5 Загруженность | сопоставимо | сопоставимо | зависит от планировщика |
| Q6 COUNT(*) | ~3 мин | ~2 сек | CRDB выигрывает (параллелизм) |

> Вывод: PostgreSQL single-node быстрее на аналитических запросах с JOIN и window functions.
> CockroachDB выигрывает на простых агрегациях по большим таблицам за счёт параллельного выполнения.
> Главное преимущество CockroachDB — горизонтальное масштабирование и отказоустойчивость, а не скорость одиночных запросов.
